## 3. 逐页讲稿

### 第 1 页：证据边界，比回答更重要

**时间：25 秒**

各位老师好，我汇报的课题是“基于预定义知识图谱的轻量化混合 GraphRAG 机器学习知识问答 Agent”。项目的核心不是让模型尽量多回答，而是让回答、部分回答和拒答都能追溯到证据。系统固定覆盖 6 个 scikit-learn 官方页面；扩展实验包含 23 题、4 种方法和 92 次问答调用；当前分支 143 项自动化测试通过，Partial-pass 在 extension 中没有泄漏被判为不支持的 Claim。

**转场：** 为什么把证据边界放在回答能力之前？因为小型知识库同样会出现三类失败。

**不要说：** “0 个不支持 Claim 泄漏”等于“系统绝对不会产生幻觉”。它只表示冻结 extension 样本中的观察结果。

### 第 2 页：研究问题

**时间：35 秒**

以“随机森林为什么更稳定”为例，系统可能有三类错误。第一是漏答，只找到一部分路径或机制；第二是误答，虽然给出了引用，但专业结论并没有被引用直接支持；第三是过度拒答，部分结论已经有证据，却因为另一条结论验证失败而整题拒绝。本项目的研究目标不是强行回答，而是让 `PASS`、`PARTIAL_PASS` 和 `REFUSE` 都有结构化、可审计的依据。

**转场：** 为了做到这一点，我先主动压缩了知识范围。

### 第 3 页：6 页官方文档形成可追溯知识边界

**时间：35 秒**

知识库只使用线性模型、支持向量机、决策树、集成学习、聚类和指标评估 6 个官方页面，共切分为 180 个稳定 ID 的 Chunk。文本层使用 TF-IDF 检索并保留逐字 quote；结构层包含 50 个实体和 100 条经过审核的关系。运行时通过 E ID 表示文本证据、P ID 表示图路径、R ID 表示审核关系，因此每条 Claim 都能回到具体来源。

**转场：** 在这个固定边界上，主链路把稳定判断与语言生成分开。

### 第 4 页：系统架构

**时间：55 秒**

用户问题首先进入规则 Router，由规则判断意图，并选择 Vector、Graph 或 Hybrid 检索。这里没有使用 LLM Planner，因为本地 `qwen3:4b` 的 QueryPlan 探针虽然 20 次都能输出合法 JSON，但只有 1 次语义正确。检索结果进入 Evidence Packer，完成去重、题型配额和可见 E、P、R ID 边界控制。LLM 只在 answer 节点把证据组织成最多 4 条原子 Claim；如果 Ollama 运行失败，系统会显式回退到规则生成器。最后由确定性 Claim-level Verifier 分别核验引用、quote、术语、图路径和问题限定条件。只有 0 条 Claim 可保留时，系统才扩大到 Hybrid Top-K 并最多重试一次。

**转场：** 这套设计里最关键的变化，是验证粒度从整段答案下降到单条 Claim。

**必须强调：** Rule Router 固定，LLM 不参与规划和检索；fallback 是运行故障降级，不是实验中的隐藏替换。

### 第 5 页：逐 Claim 保留与 Partial-pass

**时间：55 秒**

这页用脱敏 DEV02 展示机制。Evidence Pack 给出文本、路径和关系证据，LLM 生成 4 条原子 Claim。Verifier 对每条 Claim 单独处理：C1、C2 的 quote 和 ID 有效，因此保留；C3 的 quote 或术语覆盖不足，C4 超出当前证据边界，因此删除。最终状态不是整题拒答，而是 `PARTIAL_PASS`，答案只由保留的 2 条 Claim 重新构造，并明确披露剩余方面证据不足。这个 smoke 中 retry 为 0，unsupported leakage 为 0。它证明的是过滤机制按设计工作，不代表整体回答质量已经提高。

**转场：** 这套状态和运行过程也被直接暴露在用户界面中。

### 第 6 页：真实运行界面与可观测性

**时间：35 秒**

这张图是 Stage 8.4 的真实 Streamlit browser smoke。界面不仅显示答案和证据，还显示 Verifier 决策、检索模式、Claim coverage、模型、requested 和 actual backend、fallback、结构化输出状态，以及检索、生成、验证、重试和端到端延迟。截图中的 `PARTIAL_PASS`、0.50 coverage 和 7845 毫秒只属于这次工程 smoke，用来证明界面和 trace 可用，不作为正式质量或性能指标。

**转场：** 有了可观测主链路，还需要避免实验过程本身污染结论。

### 第 7 页：先冻结、再运行、后解盲

**时间：45 秒**

实验治理分为六步。10 道 dev 题只用于实现调试；40 道 pilot 只做一次冻结前回归；随后在提交 `e207cb9` 上冻结 Prompt、runtime、模型和方法合同。Extension 使用 23 题比较 4 种方法，共 92 次调用，只运行一次。人工评分阶段先使用匿名 A、B、C、D 方法标签，92 行评分经用户审核确认后才读取 method key 解盲。final、pilot 和 extension 都已消费或冻结，所以后续不重跑、不覆盖，也不根据逐题结果继续调参。

**转场：** 先看历史规则基线，它提供了一个稳定保底。

### 第 8 页：v1 规则基线

**时间：35 秒**

v1.0 是不包含 LLM 的规则生成基线。在冻结的 40 题 final 上，pass 或 refuse 决策为 39/40，4 道无答案题全部正确拒答，平均本地工作流耗时为 1.48 毫秒。唯一错误是 AdaBoost 定义题被保守拒绝。这组结果证明规则热路径在固定边界内很稳定，但样本较小，而且这里报告的是决策准确率，不能直接替代 extension 的人工回答正确性。

**转场：** 引入 LLM 后，结果不再是单一指标上的简单提升。

### 第 9 页：Extension 回答质量

**时间：55 秒**

23 题 extension 的用户确认结果显示没有单一赢家。Rule 的 Correctness 为 0.5870，Faithfulness 为 0.8810。Strict 的 Faithfulness 是 1.0000，但只有 3 条实质答案进入分母，同时大量可回答题被拒绝。No Verifier 的 Correctness 最高，为 0.7826，可读性也较高，但 Faithfulness 降到 0.8182，并出现 6/22 的观察 hallucination。Partial-pass 的 Correctness 为 0.5217，没有超过 Rule；Faithfulness 为 0.9375，在 16 条实质答案中没有观察到 hallucination。这里必须把指标值和有效分母一起看。

**转场：** 因此更合适的解释不是谁全面胜出，而是安全与覆盖之间的权衡。

### 第 10 页：安全与覆盖权衡

**时间：50 秒**

横轴是 19 道可回答题中的 over-refusal，纵轴是实质答案中的观察 hallucination，两者分母不同。Rule 为 O 0/19、H 0/21；Strict 为 O 16/19、H 0/3，说明它主要通过拒答保持忠实；No Verifier 为 O 0/19、H 6/22，覆盖高但证据风险明显；Partial-pass 为 O 5/19、H 0/16。由此可以说，Partial-pass 相比 Strict 缓解了过度拒答，同时在当前样本中保持零观察 hallucination；但它仍有覆盖代价，也不能主张统计显著性或绝对安全。

**转场：** 除了质量与安全，LLM 还带来很现实的工程成本。

### 第 11 页：本地延迟

**时间：35 秒**

这张图使用对数横轴。Rule Baseline 平均 5.46 毫秒；三个 LLM 方法约为 5.21 到 11.89 秒，其中 Partial-pass 为 7.61 秒。Stage 8.5 的分阶段 trace 显示，约 9420 毫秒端到端耗时中，模型生成占约 9409 毫秒，所以瓶颈主要在本地模型生成，而不是检索或验证。这是单机本地受控结果，不能外推到其他硬件。

**转场：** 最后，我把项目已经证明和仍未证明的内容分开总结。

### 第 12 页：结论与下一步

**时间：45 秒**

项目已经完成从官方页面、预定义图关系、文本证据、原子 Claim、确定性验证到冻结实验的可审计闭环。结果支持三点：图关系与官方 Chunk 可以形成可追溯证据链；Claim-level Partial-pass 相比 Strict 能缓解过度拒答；Verifier 对错误前提、无答案题和不受支持 Claim 有直接作用。同时必须保留三点限制：Partial-pass Correctness 0.5217 未超过 Rule 的 0.5870；LLM 仍有秒级延迟；6 页语料、23 题 extension 和单一用户确认不能支持广泛泛化。下一步优先做属性存在性验证、多跳 required-aspect 覆盖和独立双人标注。

**结束语：** 我的贡献重点是证据控制、可审计运行和严格实验治理，而不是提出新的基础模型。谢谢各位老师。

## 4. 备份页讲稿

### 第 13 页：四方法矩阵

**何时打开：** 老师追问“消融是否公平”“四种方法究竟差在哪里”时。

四种方法都使用固定 Rule Router。Rule Baseline 使用规则生成；另外三种方法都使用同一个 `qwen3:4b`、相同 Evidence Packer、Prompt v2 和生成参数。Strict 与 Partial-pass 的主要差异是 Verifier 的决策粒度；No Verifier 保留 shadow 验证记录但不干预答案。因此 extension 能把主要差异归因到生成与验证策略，而不是路由或检索器变化。

### 第 14 页：可声明贡献与边界

**何时打开：** 老师追问“是不是完整 GraphRAG”“是否用了 Dense Retrieval”“是否已经全面优于规则”时。

准确表述是“基于预定义知识图谱的轻量化混合 RAG”或“Knowledge-Graph-Enhanced RAG”。项目没有实现 Microsoft GraphRAG 的社区检测和全局摘要，没有自动抽取图谱；当前正式检索不能称为神经 Dense Retrieval；LLM Planner、Neo4j 正式部署基准和完整 scikit-learn 泛化也没有完成。可以确认的是：项目实现了证据绑定、Claim-level 过滤、可解释拒答和可审计实验闭环。
