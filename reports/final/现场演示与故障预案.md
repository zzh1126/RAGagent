# 轻量化混合 GraphRAG 现场演示与故障预案

## 1. 演示边界

现场演示只验证当前系统能够运行、展示真实模型参与、返回证据、执行 Claim-level 验证并在证据不足时拒答。它不是新增实验，不产生新的科研指标，也不能替代已经冻结的 final、pilot 或 extension。

允许使用：

- `data/evaluation/demo_questions.jsonl` 中的演示题；
- 单条 CLI 或 Streamlit 工程 smoke；
- 已提交的 Streamlit 截图和答辩 PPT；
- `offline_rule` 故障回退。

禁止执行：

- `python scripts/run_evaluation.py --split final`；
- `python scripts/run_evaluation.py --split pilot`；
- `python scripts/run_extension_evaluation_v2.py ...`；
- 修改冻结 Prompt、配置、题集、release、receipt 或实验输出；
- 根据现场答案临时调参或反复选择“最好看”的结果。

## 4. 推荐现场演示流程

总时长建议控制在 2～3 分钟。只用已登记 demo 题，不临时发挥。

### 第一步：结构关系题 DEMO01

输入：

```text
请给出随机森林的模型族归属。
```

预期展示重点：

- 系统识别随机森林实体；
- 返回“随机森林属于集成学习”或等价证据支持结论；
- 展开图路径，指出实体、关系和 relation ID；
- 指出当前 Generator、backend、fallback 和结构化输出状态。

讲解口径：

> 这道题展示预定义图关系与文本证据如何共同约束一个单跳事实。现场输出是工程 smoke，正式结论仍来自冻结实验。

### 第二步：机制题 DEMO02

输入：

```text
随机森林降低方差的机制是什么？
```

预期展示重点：

- 检索模式通常为 Hybrid；
- 展示文本证据和图路径；
- 决策可能是 `PASS` 或 `PARTIAL_PASS`，以实际验证结果为准；
- 若为 `PARTIAL_PASS`，指出保留 Claim、删除 Claim 和 coverage；
- 展示 LLM generation 与端到端延迟，不承诺固定秒数。

讲解口径：

> 关键不在于现场一定出现哪个状态，而在于每条保留结论必须绑定可见证据；不受支持的内容不会进入最终正文。

### 第三步：属性拒答题 DEMO07

输入：

```text
随机森林是否有学习率参数？
```

预期展示重点：

- 当前 6 页知识库没有足够直接证据支持该属性判断；
- Verifier 在无可保留 Claim 时最多执行一次 Hybrid retry；
- 最终应保守 `REFUSE`，并显示证据不足说明；
- 拒答不等于现实世界中该问题没有答案，只表示当前知识边界不足。

讲解口径：

> 系统拒绝的是“在当前证据边界内作出可靠判断”，而不是使用模型记忆补齐答案。

### 不建议现场使用的题

- 不使用临时改写的 XGBoost 问题；离线规则 fallback 对未登记改写可能返回相关但不对题的通用树模型答案；
- 不把 `DEMO08` 作为主演示题；它只保留为数据集中的范围外拒答检查；
- 不现场输入涉及最新版本、完整 API 或 6 页知识库之外的开放问题；
- 不为了获得更漂亮结果而重复运行同一题。

## 5. 演示时必须指出的界面信息

1. `Decision`：`PASS`、`PARTIAL_PASS` 或 `REFUSE`；
2. `Generator`：应显示 `qwen3:4b`，离线模式显示 Offline rule；
3. `Backend`：requested backend 到 actual backend；
4. `Fallback`：是否发生自动降级；
5. `Structured JSON`：真实 LLM 结构化输出是否成功；
6. `Claim coverage`：保留 Claim 占生成 Claim 的比例；
7. `Graph paths`：实体、关系和关系 ID；
8. `Official evidence`：E ID、Chunk ID、原文和官方 URL；
9. `Latency`：检索、packing、LLM、验证、retry 和端到端耗时；
10. `Trace`：每轮 retrieval、generation、packing 和 verification 的实际调用。

## 6. 故障分级与处理

### A. Ollama 未启动

**现象：** LLM Client 报连接失败；界面显示 fallback 为 true。

**现场处理：** 不停留在下载或排障。先明确说明系统进入设计好的故障降级路径，然后用离线模式继续：

```powershell
$env:AGENT_GENERATOR_BACKEND='offline_rule'
python -m streamlit run app/streamlit_app.py --server.port 8502
```

打开 `http://127.0.0.1:8502`。讲解：

> 当前 Ollama 服务不可用，系统按预设合同回退到确定性规则生成器；界面会显式显示 actual backend 和 fallback，不会把规则答案伪装成 LLM 输出。

### B. `qwen3:4b` 模型缺失

**现象：** `ollama list` 没有 `qwen3:4b`，请求返回 model not found。

**现场处理：** 不现场下载模型，直接使用 `offline_rule` 或 PPT 第 6 页的已验证截图。答辩后再执行：

```powershell
ollama pull qwen3:4b
```

### C. LLM 响应过慢或超时

**现象：** 单题等待明显超过平时；可能触发 Client 重试或 fallback。

**现场处理：** 最多等待当前请求一次，不连续重试。说明本地 LLM 秒级延迟本就是已报告限制，然后切换离线模式或使用 PPT 截图。不要改 `timeout_seconds`、`num_predict` 或 Prompt。

### D. 8501 端口被占用

**现象：** Streamlit 提示 port already in use。

**处理：** 使用 8502：

```powershell
python -m streamlit run app/streamlit_app.py --server.port 8502
```

### E. `chromadb`、`sentence_transformers`、`langgraph` 或 Streamlit 缺失

**现象：** `ModuleNotFoundError`。

**答辩前处理：** 在有网络时安装并复查：

```powershell
python -m pip install -r requirements.txt
python -c "import chromadb, sentence_transformers, langgraph, streamlit; print('dependencies ok')"
```

**现场处理：** 不在现场长时间安装大型依赖，改用 PPT 截图和冻结结果讲解。若只有 LangGraph 缺失，项目有本地状态机兼容路径，但不能把它说成当前正式 LangGraph 运行。

### F. 页面空白、浏览器打不开或 Streamlit 崩溃

**处理顺序：**

1. 检查启动窗口是否仍显示服务地址；
2. 手动打开 `http://127.0.0.1:8501`；
3. 刷新一次浏览器；
4. 若仍失败，运行 CLI demo：

```powershell
python scripts/run_agent.py "随机森林降低方差的机制是什么？"
```

5. CLI 也失败时，使用 PPT 第 6 页截图和本文件中的已验证 smoke 记录。

### G. 现场没有互联网

系统运行不依赖重新抓取网页：6 页 HTML、180 个 Chunk、图数据和本地模型均已在本机。官方 URL 可能无法打开，但界面中的缓存证据仍可展示。不要现场运行抓取脚本。

### H. 现场答案与预期措辞不同

LLM 输出可能有轻微措辞差异。先检查是否绑定真实证据、Verifier 状态和 unsupported Claim 过滤，不根据措辞差异临时改代码或重跑。若出现明显异常，直接说明这是单次工程 smoke，并回到冻结实验和 PPT 截图。

## 7. 一键切换与恢复

### 强制离线规则模式

```powershell
$env:AGENT_GENERATOR_BACKEND='offline_rule'
python scripts/run_agent.py "随机森林为什么更稳定"
```

### 恢复默认 LLM 模式

```powershell
Remove-Item Env:AGENT_GENERATOR_BACKEND -ErrorAction SilentlyContinue
python scripts/smoke_llm_client.py --timeout 180
```

环境变量是在当前 PowerShell 会话中生效。切换模式后需要重新启动 Streamlit，已经缓存的 workflow 不会自动重建。
